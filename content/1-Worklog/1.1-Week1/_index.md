### Achievements

- Got acquainted with the FCAJ team, communication channels, and the expected way to ask questions and report progress.
- Reviewed the internship guidelines and recorded the key requirements, work etiquette, security expectations, and administrative steps.
- Confirmed that account access and any cloud resources should be created only under the approved instructions.
- Prepared the required development tools and organized the assigned learning materials.
- Reviewed safe handling of credentials, the purpose of MFA, and the importance of avoiding root-user access for routine work.
- Identified the need to check billing, budgets, and clean up lab resources after practice.
- Learned how an AWS account provides the boundary for managing cloud resources, billing, identity, and regional services.
- Reviewed AWS Budgets as a way to set spending thresholds and receive alerts; a budget is a monitoring mechanism, not a hard spending cap by itself.
- Learned where to find AWS Support and documentation when troubleshooting a service or account issue.
- Organized the major service groups—compute, storage, networking, databases, security, and monitoring—by their typical responsibilities.
- Learned how IAM users, groups, roles, and policies define who can perform which actions on AWS resources, with least privilege as the guiding principle.
- Distinguished identity-based permissions from the role an application or AWS service assumes to access another service.
- Reviewed VPC, CIDR ranges, public and private subnets, route tables, internet gateways, and security groups as the building blocks of network isolation.
- Recognized that network access requires both correct routing and appropriate security rules.

### Lessons Learned

- Set up cost alerts and least-privilege access before creating resources.
- Network design (subnets, routing, security groups) decides what can reach what.
